# 03 · 大模型交互记录指南

> 任务书要求：每组保留 **3–5 段**关键对话，注明所用模型、验证方法和结论；
> 每段关联**学生判断、实际实验与证据位置**。占分 20，是独立评分维度。

## 一、流程：必须"先假设、后提问、再核验"

1. **先提假设**：每位成员独立写下自己的判断（如"BF 失败率一定低于 FF"），说明理由；
2. **再问模型**：给出完整规则与输入，要求模型解释依据、提出检验方法；
3. **运行核验**：用程序 + 手工推演验证模型说的对不对；
4. **作判断**：采纳 / 修改 / 拒绝模型的建议，写明证据位置。

## 二、提问模板（任务书参考句式）

> "在以下明确假设下，请检查我提出的假设，指出依赖的前提，
> 并提出一个能够区分两种解释的小型实验。"

本题可用的具体提问示例：

- "在连续内存分配（First Fit 按地址递增、Best Fit 选最小可装下块、同长取低地址、
  不做紧缩）假设下，请比较两种策略的碎片表现，指出我的假设依赖的前提，
  并构造一个能区分两策略表现差异的申请/释放序列（≤20 步）。"
- "以下序列运行后第 6 步申请 50 失败：空闲总量 60，空闲块 [0,30)、[60,90)。
  请解释失败原因，并判断这是否意味着内存已耗尽？"
- "请解释释放 [30,60) 时如何处理相邻空闲区，左侧 [0,30) 空闲、右侧 [60,90) 已分配
  时应合并成什么？"

```

- 实际提问（原文）：__

- 学生判断：采纳 / 修改 / 拒绝，理由：__
```

**提交时保留实际问答原文，不得只交模板。** 原始链接或截图可作补充。

## 四、本题重点核验点：模型容易混淆的三个指标

评分点之一是"检查模型是否把以下三者混为同一指标"，提问后要主动核对：

| 概念 | 含义 | 常见混淆说法 |
|------|------|--------------|
| **空闲总量** | 所有空闲块长度之和 | "还有 60 可用，肯定能分配 50" ← 错，忽略连续性 |
| **最大空闲块** | 最大一块的长度 | 决定连续申请能否成功的**唯一**标准 |
| **"最佳"适应** | 本次选块标准的"最佳"（剩余碎片最小） | "Best Fit 整体效果一定最好" ← 错，它会切碎大块 |

若模型回答中出现类似混淆，**明确指出并修正**，这就是很好的"学生判断"素材。

## 五、建议的 3–5 段交互选题

1. 请模型比较 FF 与 BF 并构造**体现差异的序列** → 运行核验（任务书指定动作）；
2. 请模型解释**碎片失败原因与合并规则** → 核对其是否混淆三个指标（任务书指定动作）；
3. 请模型评价"**Best Fit 总体优于 First Fit**"这类绝对化判断 → 构造反例或说明边界；
4. 请模型审查**三种合并的实现思路**（尤其双侧合并）→ 用边界案例验证；
5. 请模型对某个具体布局**预测下一步申请结果** → 手工推演对照。

## 六、红线

- 不能直接把模型回答当作结论；
- 每位成员都要参与提问或核验（可分工不同交互段）；
- 问答必须是真实发生的，保留原文。
