# 05 · 报告模板说明（LaTeX）

本项目的报告模板**基于课程所在学校的论文模板库改写**，不是自拟版式。
本文说明模板来源、选型理由、编译方法与改写要点。

## 一、模板来源

模板库：`Paper_Library`（汕头大学课程报告 LaTeX 模板库，XeLaTeX）

| 目录 | 用途 |
|---|---|
| 软件工程实验报告模板/ | 实验报告（封面+目录+实验记录+讨论） |
| **计算方法实验报告模板/** | **含算法伪代码与代码高亮的实验报告（本项目基线）** |
| 思政课程论文模板/ | 思政课课程论文 |
| Python课程项目技术报告模板/ | 开发实训项目技术报告 |

本地路径：`~/Documents/coding/Paper_Library`（独立仓库，本项目只取版式基线，不复制其正文）。

## 二、为什么选「计算方法实验报告模板」

题目五本质是**算法实现与比较实验**（首次适应 vs 最佳适应），与方法类实验报告的结构逐项对应：

| 报告章节 | 对应任务书要求 |
|---|---|
| 封面 | 题号、组号、成员、指导教师 |
| 1 问题与假设 | 研究问题 + 模型约定 + 六人各自提出的假设（"假设与规则"5 分） |
| 2 方法 | 两种策略、合并规则、三项检查、**四步验证流程**、三组序列设计 |
| 3 关键实验 | 案例 3 碎片失败、案例 1 策略分歧、三种合并、约束检查、人工核对 |
| 4 模型建议核验 | 四步法中"再讨论"与"作判断"：模型建议 → 我们的核验 → 采纳/修改/拒绝 |
| 5 结论与局限 | 五条结论（对应 A1–D1 的判定）+ 三条局限 |
| 附：小组分工 | 六人分工、对应假设、职责 |

结构完全按任务书的逻辑链组织；摘要与代码附录不放，目录保留但不编页码，正文控制在 6 页。

## 三、文件与编译

```
report/
├── report-template.tex        小组报告（9 页：封面 + 目录 + 编号正文 7 页）
├── assets/logo.png            校徽（取自模板库）
├── Makefile                   make / make clean
└── *.pdf                      编译产物
```

```bash
cd report
make                      # 等价于 xelatex 跑两遍
make clean
```

环境：TinyTeX（`~/.TinyTeX`，TeX Live 2026）+ 宏包 `ctex`、`zhnumber`、`xecjk` 等。
中文默认用 ctex 自带的 **fandol** 字体，Linux/Windows/macOS 均可编译；
若要与本机系统字体一致，可在 `\documentclass` 加 `fontset=mac`（或 `windows`）。

## 四、相对模板库的改写内容

1. **标题与身份要素**：封面改为「操作系统原理课内实践项目报告」+ 题目五，字段换成组号、小组成员（5 人）、专业、指导教师。
2. **章节骨架保留**：模型构建 → 算法实现 → 结果与分析 → 结论 → 附录（代码、分工、AI 使用）与基线一致，评审读起来熟悉。
3. **新增内容**：
   - `\membar` 命令：用 TikZ 画**内存布局条形图**（空闲绿 / 已分配蓝，上方地址刻度，宽度自动适配行宽），报告里的状态图不必截图；
   - 附录 B「小组分工与贡献」，对应任务书五人分工表；
   - 附录 C「AI 工具使用说明」，改写为**大模型核验**口径（任务书要求保留学生判断，不是单纯声明）。
4. **公式化表述**：候选集 $\mathcal{C}(w)$、选块规则 $\arg\min$、合并四情形、成功判据 $\max \ell_F \ge w$ 均写成公式，便于逐条核对与答辩引用。

## 五、篇幅与页码约定

正文 7 页（编号 1–7）。每章另起一页、附录单独一页：

| 部分 | 页数 | 页码 |
|---|---|---|
| 封面 | 1 | 不编号 |
| 目录 | 1 | 不编号（`\pagestyle{empty}`） |
| 1 问题与假设 | 1 | 1 |
| 2 方法 | 1 | 2 |
| 3 关键实验 | 2 | 3–4 |
| 4 模型建议核验 | 1 | 5 |
| 5 结论与局限 | 1 | 6 |
| 附：小组分工 | 1 | 7 |

合计 9 页，编号页 7 页。每章用 `\clearpage` 另起一页，附录单独一页，
因此各章末页留白属正常现象。

不放摘要、关键词与代码附录。代码与原始轨迹在仓库中（提交包附源码），
报告里只做引用，避免正文被撑长。表格与图允许浮动（`[htbp]`），
以免 `[H]` 强制定位造成半页空白。

若仍需压到 4–5 页，可删图 2（案例 1 布局图，表 4 已含布局信息）与"人工核对"段。

## 六、填写与自查

- 封面、附录 B 的成员信息须与仓库 README 的分工一致；
- 表 2（假设表）、附录 C（AI 使用）必须换成**真实**内容：本组每位成员的初始假设、真实问答与核验结论；
- 文中与仓库的引用路径（`experiments/…`、`web/…`）须与最终仓库一致；
- 提交时记录**演示网址对应的 commit SHA**，与报告封面一并核对。

## 七、已知排版细节

- `\membar` 的标签用短名（如 `空闲`、`B`），地址由上方刻度标出；标签留空则只画色块；
- 块窄时（如长度 10/100）标签可能略挤，可改 `\scriptsize` 为 `\tiny` 或省略标签；
- 代码附录用 `\codefile{...}` 引入，文件不存在时输出占位提示，保证模板可独立编译。
