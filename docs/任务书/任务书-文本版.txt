操作系统课内实践| 第5 页
附录题目一
进程调度策略的比较与验证
一、任务要求
研究问题：一种调度算法的平均等待时间较短，是否意味着每个进程都能得到更好的服务？
时间片变化会怎样影响首次响应和完成时间？
实验范围：采用单CPU 离散时间模型。每个进程只有一段CPU 执行时间，执行时长预先已
知，不含I/O 和切换开销。到达时间为非负整数，执行时长和时间片为正整数，每例三至六个进
程。
1. 实现FCFS、非抢占SJF、时间片轮转RR。到达同时及SJF 执行时长相同时，用固定规则打破
平局；RR 时间片到期与新进程到达同时发生时，也应声明入队顺序。
2. 设计三类负载：任务同时到达、长短任务混合、任务错时到达。同一案例使用相同输入比较三
种算法；RR 至少比较两个时间片。
3. 输出甘特图或等价时间轨迹，列出每个进程的首次运行时间、完成时间、响应时间、周转时间
和等待时间，并汇总平均值与最大等待时间。
4. 完整手算至少一个案例，与程序逐项核对。再构造或修改一个案例，检验“平均值较好是否意味
着每个进程都更好”，解释一个指标改善时其他指标可能发生的变化。
演示程序：页面可输入进程表、切换算法和时间片，运行后显示时间轨迹与逐进程指标；至
少内置三类案例，支持重置与保存输入和结果。
二、大语言模型使用方式
1. 给出模型假设与具体负载，请大模型针对算法的表现提出假设并说明理由；把模型与组员各自
提出的假设分别保存。
2. 要求模型尝试构造能推翻某个绝对化判断的输入。运行验证后，追问差异来自算法、实现还是
前提条件。

操作系统课内实践| 第7 页
附录题目二
页面置换策略与缺页现象验证
一、任务要求
研究问题：给程序分配更多页框，缺页次数是否一定减少？FIFO、LRU 和Clock 的表现受哪
些访问模式影响？
实验范围：模拟单进程页访问，页框初始为空，页号为非负整数，页框数取二至五。每条访
问序列不超过三十次；若反例搜索需要更长序列，应说明理由并保留一个便于人工核对的短例。
1. 实现FIFO、LRU 和Clock。写清Clock 的初始指针位置、装入与命中时引用位的更新方式，以
及指针移动规则。
2. 设计循环访问、局部集中访问、局部访问夹杂一次性扫描三类序列。在相同输入与相同页框数
下比较三种算法。
3. 每次访问都输出访问页、命中或缺页、被淘汰页和访问后页框；Clock 另列引用位和指针。分
别报告缺页次数与缺页率。
4. 人工推演一条不超过十二次访问的短序列。寻找并验证FIFO 的Belady 异常实例，比较至少两
个页框数；再检查LRU 在同一输入上的变化并解释原因。
演示程序：页面可输入访问序列和页框数，切换算法，逐步或一次运行；同时展示页框轨迹
和比较表。预置案例应能直接重现报告中的主要现象。
二、大语言模型使用方式
1. 请模型评价“页框越多缺页一定越少”“LRU 对任何序列都优于FIFO”等判断，要求其说明条件并
给出可验证的序列。
2. 逐步核对模型给出的置换过程；若其反例不成立，定位第一次出现差异的访问，再修改输入或
实现。

操作系统课内实践| 第9 页
附录题目三
生产者消费者同步的分析与验证
一、任务要求
研究问题：程序多次正常结束能否证明同步正确？互斥与条件等待分别解决什么问题，为什
么等待条件需要重新检查？
实验范围：两个生产者、两个消费者，缓冲区容量为二或三。每个生产者生成十个唯一编号
数据，并明确停止规则。可用浏览器离散步骤模拟线程交错；也可用C 与POSIX 线程实现真实
并发。两条路径按同一原理和证据标准评分。
1. 定义缓冲区、锁、条件变量和线程状态。说明等待如何释放锁，以及被唤醒后如何重新获得
锁；正确版本必须在受保护条件下检查共享状态。
2. 完成生产和消费流程，检查缓冲区不越界、每个数据恰好消费一次，以及全部任务能结束。真
实线程路径需保留原始运行记录；模拟路径需显式实现上述状态转换。
3. 比较正确版本与一份明确含同步缺陷的版本。可选择将条件等待的while 改为if，并配合适当
唤醒与调度顺序展示问题；仅替换关键字但未触发错误，不算完成分析。
4. 画出导致问题的执行交错，并用可重放的调度序列或受控运行复现。修复后对同一序列复测，
再补充至少两种调度或负载变化。
演示程序：网页显示队列内容、各线程状态、锁持有者、条件等待队列和操作日志，可切换
正确与缺陷版本并重放交错。真实线程程序可配套网页回放原始日志。页面必须标明证据来自模
拟还是实际线程运行。
二、大语言模型使用方式
1. 请模型解释互斥与条件等待的职责，审查正确版本，并提出可能暴露缺陷的交错；要求其列出
每一步的锁和缓冲区状态。
2. 核验模型建议能否真实触发问题，检查“多运行几次”“增加sleep”等建议是否构成充分验证。

附录题目四
资源分配安全性与死锁状态辨析
一、任务要求
研究问题：银行家算法拒绝一次请求，是否表示系统已经死锁？最大可能需求和当前实际等
待分别影响什么判断？
实验范围：最多四个进程、三类可重复使用资源，资源数量为非负整数。资源正常使用完可
以释放，暂不考虑抢占与故障。分别维护资源总量、可用量、当前分配、最大需求，以及当前实
际请求或等待。
1. 实现安全性检查与资源请求处理。请求先检查是否超过尚需量或可用量，再试分配并检查安全
性；不满足条件时保留原状态并说明原因。
2. 构造三类状态：安全、不安全但当前尚未死锁、实际已经死锁。每类都给出分配和最大需求；
判断实际死锁时，另给出当前等待及相关进程能否继续推进或释放资源。
3. 为安全状态给出一个安全序列；对于没有安全序列的状态，展示检查停止的位置和原因。资源
释放后，应重新检查并显示状态变化。
4. 选择同一资源请求，比较直接分配与经银行家算法检查后的结果。逐步展示两条路径，并解释
拒绝请求的依据以及与实际死锁的区别。
演示程序：网页可编辑资源表，发出请求或释放资源；显示试分配前后、安全性检查步骤及
安全序列。实际等待信息应独立展示，不能把“不安全”直接标成“已死锁”。
二、大语言模型使用方式
1. 先请模型根据同一组数据判断安全性，再补充当前实际请求，请其判断是否已经死锁，检查两
次回答使用了哪些不同信息。
2. 要求模型解释最大需求、尚需量与当前等待的区别；用人工安全性检查与执行过程验证回答。

连续内存分配与碎片问题验证
一、任务要求
研究问题：空闲内存总量足够时，为什么一次连续内存申请仍可能失败？最佳适应依据什么
标准作选择？
实验范围：模拟大小固定的一块连续内存，初始为完整空闲区。采用整数地址与正整数申请

仅右侧合并、两侧同时合并的释放案例。
4. 检查已分配区不重叠，已分配量与空闲量之和恒定，相邻空闲块已合并。处理重复释放和非法
申请，且失败操作不破坏原状态。人工推演至少一组序列。
演示程序：网页支持输入操作序列、切换策略、单步执行和重置，展示带地址的内存布局及

2. 请模型解释失败原因和合并规则，检查其是否把空闲总量、最大空闲块或“最佳”混为同一指

操作系统课内实践| 第15 页
附录题目六
文件创建中断与一致性恢复
一、任务要求
研究问题：创建文件需要修改多个持久化位置，中间发生故障会留下什么状态？怎样通过简
化日志恢复到合法状态？
实验范围：建立极小文件系统模型：目录表、空闲块位图、数据块，另设独立日志区。可取
十六个数据块，每个文件占一块，只处理串行创建。每次模型写入原子完成，按指定顺序立即持
久化；故障只发生在两次写入之间。
1. 定义合法状态：目录引用的块已分配且数据正确，数据块不重复归属，不存在未被目录引用的
已分配数据块。日志区独立于上述数据块统计；空闲块残留内容不代表其已分配。
2. 实现不带日志的创建，明确写数据位图和目录的顺序。枚举操作开始前、各写入之间及操作完
成后的故障点，保留持久化快照并检查一致性。
3. 设计简化的写前日志与恢复重放，明确日志记录、提交标记、实际更新和清理顺序。已提交但
未完成的更新应能恢复，未提交操作不得被误当作完成；允许保留空闲块中的残留数据。
4. 枚举日志方案各故障点，检查恢复后文件系统的可见状态是否等价于操作前或操作后。对恢复
过程再次中断至少一次，检查再次恢复是否安全，解释重放的幂等性。
演示程序：网页可选择基线或日志方案，按步骤创建、在指定写入边界注入故障并执行恢
复，展示目录位图数据和日志快照。使用内存快照或JSON 模拟持久化即可，必须标明其与真实
存储设备的差别。
二、大语言模型使用方式
1. 请模型提出写入和恢复方案，要求其对各中断点的结果分别提出假设；学生按合法状态定义审
查。
2. 追问日志自身未完成、提交后未清理、重放中再次故障等情况，判断模型是否遗漏写入阶段或
过度推广到真实磁盘。
