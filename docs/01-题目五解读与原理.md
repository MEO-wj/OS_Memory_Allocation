# 01 · 题目五解读与原理详解

> 依据：任务书第 13–14 页《附录题目五：连续内存分配与碎片问题验证》。

## 一、研究问题（报告必须回答）

1. **空闲内存总量足够时，为什么一次连续内存申请仍可能失败？**
   → 因为分配要求**地址连续**；多次分配释放后空闲内存被切成若干互不相邻的小块
   （**外部碎片**），总量虽然够，但没有任何一块能单独装下请求。
2. **最佳适应依据什么标准作选择？**
   → 在**所有能装下的空闲块中选最小的**（差距最小化），同等长度选低地址。
   它优化的是"本次留下的剩余碎片最小"，**不等于**整体负载下效果最佳——
   它会把大块也切碎，长期反而容易把内存变成一堆微小不可用块。

## 二、模型定义（成员一负责成文）

| 项 | 约定 |
|----|------|
| 内存 | 一块大小固定 `TOTAL` 的连续内存，地址 `0 .. TOTAL-1`，整数地址 |
| 初始状态 | 整块内存是一个空闲区 `[0, TOTAL)` |
| 申请量 | **正整数**；申请使用**唯一编号**（如 A、B、C…），用于后续释放 |
| 管理开销 | 不计（忽略块表、头部等元数据） |
| 紧缩 | **不做**（不允许搬移已分配区来拼接空闲块） |
| 序列长度 | 每组操作序列 ≤ 20 步 |
| 切割方式 | 分配时从选中空闲块的**低地址端**切出 |

**状态表示**：任一时刻 = 已分配区列表（编号、起址、长度）+ 空闲区列表（起址、长度）。

**核心恒等式（守恒）**：`Σ已分配量 + Σ空闲量 = TOTAL`，每一步都必须成立。

## 三、两种分配策略

### 3.1 首次适应 First Fit
- 将空闲区**按地址递增**排列，从头扫描，取**第一个** `长度 ≥ 申请量` 的块；
- 从其低地址端切出请求量，剩余部分留作空闲块；整块恰好用完则从空闲表删除；
- 无满足块 → 申请失败，**状态不变**。

### 3.2 最佳适应 Best Fit
- 扫描**全部**空闲区，收集所有 `长度 ≥ 申请量` 的候选；
- 选**长度最小**者；**长度相同时选地址最低**的；
- 切割、失败处理同上。

### 3.3 释放与合并（member4 重点，三种情况必须全覆盖）

释放编号 X 的区后，按其前驱/后继邻居是否空闲决定：

| 情形 | 条件 | 结果 |
|------|------|------|
| ① 仅左侧合并 | 前一相邻块空闲 | X 与左块合成一块 |
| ② 仅右侧合并 | 后一相邻块空闲 | X 与右块合成一块 |
| ③ 两侧同时合并 | 前后都空闲 | **三块合成一块**（最易出错的边界） |
| ④ 不合并 | 前后都非空闲 | X 自身成为新空闲块 |

实现建议：把 X 插入按地址排序的空闲表，然后**顺序扫描一次**做相邻合并，
可天然覆盖全部四种情形，不易漏边界。

## 四、合法性检查（评分点：守恒检查完整）

程序每步应自动检查，实验材料中要给出检查结果：

1. **不重叠**：任意两个已分配区地址区间不相交；
2. **守恒**：已分配量 + 空闲量 ≡ TOTAL；
3. **合并完整**：空闲表中任意两块都不相邻（可合并而未合并即为 bug）；
4. **重复释放**：释放不存在的编号 / 已释放的编号 → 报错且**状态不变**；
5. **非法申请**：申请量 ≤ 0、非整数、超过总内存 → 报错且状态不变；
6. **失败不破坏状态**：任何被拒绝的操作前后状态逐字段一致。

## 五、实验设计要求（任务书四条）

1. **实现**：First Fit + Best Fit + 释放合并，规则写清（查找方向、同长平局规则）；
2. **三组申请/释放序列**（每组 ≤20 步），两种策略**从相同初始状态、执行完全相同的操作**；
   至少一组出现"**空闲总量足够但最大空闲块不足**"的申请失败；
3. **逐步展示布局**（带地址），每步记录四项指标：
   **空闲总量 / 最大空闲块 / 空闲块数量 / 申请结果**；
   另构造覆盖**仅左合并、仅右合并、双侧合并**的释放案例；
4. **人工推演至少一组序列**，与程序输出逐项核对；约束检查结果一并提交。

- 展示**带地址的内存布局图**与四项指标；
- 失败申请与非法操作给出**明确原因**；

- 若用回放/模拟需注明；不能只交截图或视频。
