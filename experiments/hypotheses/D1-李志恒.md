# 假设 D1：如果失败申请也执行了切块或占位

- 提出人：李志恒 2024612066
- 提出时间：待填（须早于实验运行与模型咨询，以 git 提交时间为证）
- 负责人分工：约束检查与反例实验

## 1. 假设表述

如果失败申请也执行了切块或占位，守恒式「已分配量 + 空闲量 = 总内存」会立即被破坏。

## 2. 理由

失败不是分配，状态必须逐字段不变；一旦失败仍改动状态，守恒与后续指标全部失真。

## 3. 预期现象

错误版本在失败申请后守恒检查立即报错；正确版本全部通过。

## 4. 检验方式

- 输入：`自建错误版本 + experiments/inputs/case3-fragmentation.json`
- 操作：故意实现「失败也切块」的版本，用三项检查（不重叠 / 守恒 / 合并完整）捕获；再测重复释放、释放不存在编号、申请量 <= 0 或 > T。
- 记录：`experiments/traces/`、报告表 1

## 5. 推翻判据

错误实现下守恒仍成立（说明检查写漏了）。

## 6. 核验结论

- 判定：**支持**
- 证据位置：
  - `tools/buggy-demo.js`（故意实现"失败也切块"的错误版本）
  - `experiments/traces/buggy-version.txt`：错误版本在第 6 步后守恒检查报错
    "守恒被破坏：30+30≠90"，此后每一步都失败；正确版本 9 步全部通过
  - `experiments/traces/illegal-ops.json`：七项非法操作（重复申请、释放不存在编号、申请量 0/负/超限/非整数、重复释放）
    全部报错且状态不变
- 差异出现的位置与原因：错误版本把申请失败当成"占用了地方"，只改空闲表不登记已分配区，
  于是 已分配 + 空闲 ≠ 总内存
- 认识变化：（由本人补写）
